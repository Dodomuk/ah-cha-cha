# 아차차는 어떻게 링크를 검사하는가

이 문서는 **지금 실제로 동작하는 것**만 적는다. 계획은 [prd.md](../prd.md)에,
지켜야 할 규칙은 [CLAUDE.md](../CLAUDE.md)에 있다.

> ⚠️ 시그널을 추가·변경하면 이 문서의 표도 함께 고칠 것. 이 문서가 틀리면
> 무엇이 동작하는지 아무도 모르게 된다.

최종 수정: 2026-08-15 (Sprint 3 완료 시점)

## 1. 한 번의 검사에서 일어나는 일

사용자가 주소를 넣고 "검사하기"를 누르면 `POST /api/scan` 하나가 호출되고,
서버 안에서 아래 순서로 진행된다. **브라우저는 의심 주소에 절대 접속하지 않는다.**

```
① 정규화        입력 문자열 → 검사 가능한 URL
                 제로폭 문자 제거, 스킴 보정, 소문자화, 프래그먼트 제거
                 → 이 결과의 SHA-256이 url_hash (캐시 키)

② SSRF 가드     스킴이 http/https인가, 자격증명이 섞였는가
                 호스트를 DNS로 해석 → 나온 IP가 전부 공인 대역인가
                 하나라도 사설/예약이면 여기서 중단

③ 리디렉션 추적  최대 10홉, 총 12초 예산
                 매 홉마다 ②를 다시 통과시킨다
                 검증한 IP를 커넥션에 고정해서 연결 (DNS rebinding 차단)
                 쿠키는 심어준 도메인에만 되돌려 보낸다

④ 시그널 수집    S1·S2·S3·S4를 병렬로 조회
                 S5·S7·S8은 ③의 결과로 판단 (추가 접속 없음)

⑤ 판정          시그널 → danger / caution / unknown / no_signal

⑥ 설명 생성      Claude Haiku 4.5로 한국어 문장 생성 (5초 제한)
                 실패하면 템플릿 문구로 대체 — 판정은 그대로 나온다
```

전체 소요는 실측 1.7~4.0초다. 목표는 8초 이내([prd.md](../prd.md) 9절).

## 2. 시그널 10종의 현재 상태

판정에 실제로 쓰이는 것은 **5종**이다. 나머지는 "확인 못 함(`unavailable`)"으로
결과에 함께 실린다 — 무엇을 확인했고 무엇을 못 했는지가 판정만큼 중요한 정보라서다.

| # | 무엇을 보는가 | 상태 | 히트 시 강도 |
| --- | --- | --- | --- |
| S1 | 구글이 아는 악성 주소인가 (Safe Browsing 실시간 조회) | ✅ 동작 | `critical` |
| S2 | 피싱 신고 목록(OpenPhish)에 있는가 | ✅ 동작 | URL일치 `critical` / 호스트일치 `high` |
| S3 | 악성코드 배포 목록(URLhaus)에 있는가 | ✅ 동작 | URL일치 `critical` / 호스트일치 `high` |
| S4 | 도메인이 만들어진 지 30일 미만인가 (RDAP) | ✅ 동작 | `medium` — 단독으로는 판정을 올리지 않음 |
| S5 | 주소를 여러 번 갈아타며 여러 도메인을 거쳤는가 | ✅ 동작 | `medium` (4홉 이상 & 3개 도메인 이상) |
| S6 | TLS 인증서 발급일·발급자 | ❌ 미구현 | — |
| S7 | 유명 기관을 사칭한 도메인인가 | ✅ 동작 | 고신뢰 `critical` / 중 `high` / 저 `low` |
| S8 | 스토어를 거치지 않고 APK를 내려주는가 | ✅ 동작 | `critical` (정식 스토어면 `high`) |
| S9 | 사용자 신고가 몇 건 쌓였는가 | ⚠️ 수집만 | **판정에 반영하지 않음.** 신고는 받지만 결과 화면에 건수를 아직 안 보여준다 |
| S10 | 백신 다중 검사 (VirusTotal) | ❌ 미구현 | — |

### S9를 판정에 넣지 않는 이유

신고는 "누가 그렇게 주장했다"는 사실이지 객관적 근거가 아니다. 실존 사업자를
신고 몇 건으로 "위험"으로 표시했다가 오탐이면 명예훼손 분쟁이 된다.
판정은 엔진 근거로만 내고, 신고는 "사용자 신고 N건"이라는 사실로 따로 표시한다.

## 3. 시그널이 판정으로 바뀌는 규칙

위에서부터 순서대로 검사하고, 먼저 걸리는 것으로 확정한다.

| 순서 | 조건 | 판정 |
| --- | --- | --- |
| 1 | `critical` 히트가 하나라도 있음 | 🚨 `danger` |
| 2 | 신규 도메인(S4) + 다른 히트 1개 이상 | ⚠️ `caution` |
| 3 | `high` 히트가 있음 | ⚠️ `caution` |
| 4 | 리디렉션 추적이 실패함 | 🤔 `unknown` |
| 5 | 확인된 시그널이 2개 미만 | 🤔 `unknown` |
| 6 | 그 외 | ✅ `no_signal` |

**`no_signal`은 "안전"이 아니다.** "지금 확인한 범위에서 위험 신호가 없었다"는
뜻이고, 화면에도 그렇게만 쓴다. 새 피싱 페이지는 계속 생기고, 피싱 사이트는
방문자에 따라 다른 페이지를 보여주는 클로킹을 쓰기 때문이다.

**신규 도메인 단독으로는 판정을 올리지 않는다.** 정상 서비스도 새로 열린다.
단독 판정하면 그 순간 오탐이 발생한다.

## 4. 한국 특화 — 이게 실질적 차별점

글로벌 검사 도구들이 잘 못 잡는 영역이다.

### 브랜드 사칭 탐지 (S7)

은행 17 · 카드 8 · 택배 5 · 정부 11 · 통신 3 · 커머스 6 · 간편결제 3,
총 **53개 브랜드**의 정식 도메인을 목록으로 갖고 네 가지를 본다.

| 수법 | 예시 | 신뢰도 |
| --- | --- | --- |
| 서브도메인 사칭 | `kbstar.evil.com` | 고 |
| Homoglyph 치환 | `kbst4r.com`, 키릴 문자 `cоupаng.com` | 고 |
| 한 글자 차이 | `kbstat.com` | 고 |
| 두 글자 차이 | `kbsttat.com` | 중 |
| 경로에만 브랜드명 | `random.com/kbstar/login` | 저 |

오탐을 막는 장치가 둘 있다.

1. **짧은 라벨은 편집거리 비교에서 뺀다.** `kt`, `ibk` 같은 3글자 라벨은
   무관한 도메인과도 거리가 1~2로 나와서 그대로 쓰면 오탐 공장이 된다.
2. **정식 도메인은 즉시 통과**시킨다. 없으면 `www.kbstar.com`이 사칭으로 잡힌다.

> 퓨니코드를 되돌린 뒤에 비교한다. URL 파서가 키릴 문자 호스트를 `xn--`로
> 바꿔버리기 때문에, 이 과정이 없으면 키릴 문자 사칭이 전부 빠져나간다.

### APK 유도 탐지 (S8)

문자 → 단축 URL → APK 설치는 한국 스미싱 피해의 주 경로인데 다른 서비스가
거의 안 잡는다. 최종 목적지의 Content-Type이나 파일명, 이동 경로에 `.apk`가
있으면 위험으로 본다.

F-Droid·원스토어·삼성 갤럭시스토어만 예외로 두고 `caution`으로 낮춘다.
**GitHub Releases나 클라우드 드라이브는 넣지 않는다** — 공격자가 가장 흔히
쓰는 배포처라 목록에 넣는 순간 그게 우회 경로가 된다.

### 국내 사이트가 검사되게 만든 것 2가지

둘 다 정상 사이트가 "검사 불가"로 빠지던 문제였다.

- **쿠키 관문**: 국내 은행·정부 사이트는 쿠키를 심고 같은 주소로 302를 돌려주는
  패턴이 흔하다. 쿠키를 안 보내면 무한히 제자리를 맴돈다. 체인 동안만 쓰는
  최소 쿠키 저장소를 두되, 쿠키는 심어준 도메인에만 되돌려 보낸다.
- **구형 TLS**: OpenSSL 3가 기본 차단하는 legacy renegotiation을 허용한다.
  이게 없으면 현대카드 같은 곳이 전부 "응답 없음"이 된다.

## 5. 이 서비스 자체를 지키는 장치

악성 URL에 일부러 접속하는 서비스라 스스로가 공격 표면이다.

| 위협 | 대응 |
| --- | --- |
| 내부망·클라우드 메타데이터 접근 | 사설·예약 IP 대역 전부 차단 (169.254.169.254 포함) |
| IPv6로 감싼 우회 | `::ffff:127.0.0.1`, 16진 표기, NAT64까지 차단 |
| DNS rebinding | 검증한 IP를 커넥션에 고정. 연결 시점에 DNS를 다시 안 본다 |
| 리디렉션으로 가드 우회 | 자동 추적을 끄고 매 홉을 다시 검증 |
| 세션 값 유출 | 쿠키는 심어준 등록가능 도메인에만 전송 |
| 무한 응답·느린 응답 | 본문 512KB 상한, 홉당 6초·전체 12초 |
| 남용 | IP당 분당 10회 |

브라우저는 의심 URL에 접속하지 않는다. 우리 서버에만 요청을 보낸다.

## 6. 화면에서 지키는 원칙

기술이 아니라 신뢰의 문제라 코드로 강제하기 어렵다. 그래서 규칙으로 남긴다.

1. **"안전합니다"라고 쓰지 않는다.** 검사 시점 기준이라는 걸 항상 병기한다.
2. **위험 판정 화면에는 마스코트를 쓰지 않는다.** 귀여움은 진입장벽을 낮추는
   장치이지 경고를 무르게 만드는 장치가 아니다. 결과 화면의 두 레이아웃을
   하나로 합치면 이 규칙이 깨진다.
3. **검사한 주소를 클릭 가능한 링크로 만들지 않는다.** 도메인은 부분 마스킹하고,
   설명 문장에도 원본 주소를 그대로 쓰지 않는다.
4. **오탐이 미탐보다 비싸다.** 오탐 1건이 신뢰를 무너뜨린다.
5. **판정과 신고를 섞어 표시하지 않는다.**

## 7. 검사 말고 또 무엇이 있는가

### 결과 저장 — 위험한 것만 원문을 남긴다

검사한 주소는 사용자가 문자로 받은 링크다. 사적인 맥락이 실릴 수 있어서
판정에 따라 보관 방식을 다르게 한다.

| 어디에 | 무엇을 | 언제까지 |
| --- | --- | --- |
| Redis | 전체 결과 (깨끗한 것 포함) | 6시간 뒤 자동 소멸 |
| PostgreSQL | `danger`·`caution`만 원문 포함 | 이의제기로 정정될 때까지 |
| PostgreSQL | 그 외 판정은 해시와 판정만 | 통계 목적 |

**이 규칙은 DB가 강제한다.** `scans` 테이블에 CHECK 제약이 걸려 있어서, 깨끗한
검사에 주소 원문을 넣으려 하면 INSERT가 실패한다. 코드가 실수해도
개인정보처리방침(`app/privacy`)에 적어둔 내용과 어긋나지 않는다.

캐시 결과를 돌려줄 때는 **그 사실을 화면에 밝힌다.** 6시간 전 결과를 방금 확인한
것처럼 보여주면 그 사이 위험해진 사이트를 안전하다고 말하는 셈이다.

### 사용자 신고 — 판정을 바꾸지 않는다

신고는 "누가 그렇게 주장했다"는 사실일 뿐이므로 자동 판정에 반영하지 않는다.
쌓이면 관리자 검토 큐(`/admin/reports`)로 가고, 사람이 확인한 뒤에만 반영한다.

남용 방어는 네 겹이다.

1. **Cloudflare Turnstile** — 자동 프로그램 차단
2. **rate limit** — IP당 시간당 5회
3. **중복 방지** — 같은 사람이 같은 도메인을 두 번 신고 못 함 (DB 유니크 인덱스)
4. **검토 큐** — 쌓여도 자동 노출 안 됨

클라이언트가 도메인을 직접 보내지 않는다. 검사 결과의 해시를 보내면 서버가
캐시에서 도메인을 끌어온다 — 안 그러면 검사 한 번 없이 임의의 도메인을 대량
신고할 수 있다.

**오탐 신고는 신고 수에 세지 않는다.** `report_count`는 "이 사이트가 위험하다는
신고 수"인데 오탐 신고는 정반대 주장이다. 같이 세면 "안전하다고 신고한 사람"
때문에 위험해 보이는 역전이 일어난다.

### 공유 카드

결과를 이미지로 만들어 카톡으로 보내는 기능(`/s/{shortId}`). 부모님·지인에게
경고를 전달하는 경로다.

**카드에도 공유 페이지에도 원본 주소를 넣지 않는다.** 저장 자체를 마스킹된
형태로만 한다. 카톡으로 퍼지는 링크라, 받은 사람이 원본 주소를 눌러볼 수 있으면
경고를 전달하려던 것이 오히려 유입 경로가 된다.

공유 레코드는 사용자가 "공유하기"를 누른 순간에만 만든다. 30일 뒤 만료된다.

### 법적 문서

- `/terms` — 검사 결과는 참고 정보이며 법적 판단이 아님
- `/privacy` — 무엇을 저장하고 안 하는지, 주소가 구글로 전달된다는 사실
- `/appeal` — 사이트 운영자의 이의제기·삭제 요청 창구

이의제기 링크는 **푸터에 상시 노출**한다. 남의 사이트를 "위험"이라 표시하는
서비스에서 잘못 표시된 운영자가 항의할 곳을 못 찾으면 그건 곧 분쟁이 된다.

## 8. 알려진 약점

정직하게 적어둔다.

- **브랜드 도메인 53개가 아직 사람 눈으로 검증되지 않았다.** `verified: false`.
  하나라도 틀리면 정상 사이트가 사칭으로 잡히거나(오탐), 오타 도메인을 산
  공격자가 정식으로 통과한다(우회).
- **피드가 하루 1회만 갱신된다.** Vercel Hobby 플랜 제약. 오전에 신고된 피싱
  URL은 다음 새벽까지 S2·S3에 없다. 실시간 조회인 S1이 이 구간을 메운다.
- **Safe Browsing v4는 검사한 주소 전체를 구글로 보낸다.** v5는 해시 앞부분만
  보내지만 구현이 무겁다. 개인정보처리방침에 이 사실을 적어야 한다.
- **스크린샷이 없어서** 사용자가 그 사이트가 어떻게 생겼는지 볼 수 없다.
- **개인 검사 기록이 없다.** 예전에 검사한 사이트가 나중에 위험으로 바뀌어도
  알려줄 방법이 없다.
- **신고 처리 화면이 없다.** 검토 큐는 보이지만 승인·기각은 Supabase
  대시보드에서 직접 해야 한다.
- **신고 건수를 결과 화면에 보여주지 않는다.** 신고를 받아 쌓기는 하는데
  "이 사이트 신고 N건"을 아직 표시하지 않는다. 수집하는 이유의 절반이 빠진
  상태다. 표시할 때는 판정과 분리해서 보여줘야 한다 (CLAUDE.md 8).
- **법적 문서를 변호사가 검토하지 않았다.** 남의 사이트를 공개적으로 "위험"이라
  표시하는 서비스이므로, 트래픽이 붙기 전에 상담을 받아야 한다.
