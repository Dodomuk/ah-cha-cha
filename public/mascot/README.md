# 차차 마스코트 애셋

## 파일

| 경로 | 설명 |
| --- | --- |
| `mascot_example.png` | 원본 3x3 스프라이트 시트 (1024x1024). 이게 마스터다 |
| `poses/chacha-*.webp` | 포즈별 투명 배경 이미지. **서빙은 이걸 쓴다** |
| `poses/chacha-*.png` | 중간 산출물. git에 넣지 않는다 (WebP의 8배 용량) |

시트를 교체했거나 PNG가 필요하면 다시 만든다:

```bash
python3 scripts/slice-mascot.py
```

## 포즈 → 화면 매핑

| 포즈 | 쓰이는 곳 |
| --- | --- |
| `greet` | 홈 idle |
| `excited` | 검사 중 (임시 — 아래 참조) |
| `wink` | 결과: 이상 없음 |
| `worried` | 결과: 주의 |
| `puzzled` | 결과: 정보 부족 |
| `sleeping` | 빈 상태 (검사 기록 없음) |
| `surprised` | 예비 |
| `crying`, `angry` | **미사용** |

## 지켜야 할 것

**위험(`danger`) 판정 화면에는 마스코트를 쓰지 않는다.** 경고가 화면을 차지해야 하고,
귀여움이 경고를 무르게 만들면 안 된다 (CLAUDE.md 규칙 9).

`crying`(울음)과 `angry`(화남)가 미사용인 것도 같은 이유다. 감정상 위험 화면에
어울려 보이지만, 정작 그 화면이 마스코트를 빼는 유일한 화면이라 갈 곳이 없다.
우는 펭귄을 경고 옆에 놓는 순간 규칙 9가 막으려던 상황이 그대로 발생한다.

## 알려진 제약

1. **"뛰어드는" 포즈가 없다.** 기획서(prd.md 6.2 ②)의 검사 중 화면은 차차가 링크 안으로
   뛰어드는 애니메이션인데 해당 포즈가 없어 `excited`로 대체 중이다. 포즈가 추가되면
   `chacha-diving`으로 넣고 매핑만 바꾸면 된다.
2. **표시 크기 상한 약 160px.** 원본 시트가 1024px라 한 포즈가 약 300px이다.
   레티나(2x)에서 또렷하려면 이 이상 키우지 말 것. 더 크게 쓰려면 시트를
   2048px 이상으로 다시 뽑아야 한다.
