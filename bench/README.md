# 교차검증 벤치

라벨이 붙은 URL 묶음을 검사 엔진에 통과시켜, 우리 판정이 다른 곳의 판정과
얼마나 맞는지 본다.

```bash
npm run bench -- --set openphish --limit 100                    # 피싱 (재현율)
npm run bench -- --set urlhaus   --limit 100                    # 멀웨어 배포
npm run bench -- --set tranco    --limit 200 --band 10000-500000 # 정상 (오탐률)
npm run bench -- --set freehost  --limit 150                    # 무료호스팅 위 정상 사이트
npm run bench -- --set openphish --limit 50 --vt                # VirusTotal 대조
```

| 옵션 | 뜻 | 기본값 |
| --- | --- | --- |
| `--set` | 코퍼스 (`urlhaus` / `openphish` / `tranco`) | `urlhaus` |
| `--limit` | 표본 수 | 100 |
| `--concurrency` | 동시 검사 수 | 4 |
| `--band A-B` | 순위 목록에서 뽑을 구간 | 전체 |
| `--vt` | VirusTotal 대조 (`VIRUSTOTAL_API_KEY` 필요) | 꺼짐 |

결과는 `bench/out/`에 TSV·JSON으로 남는다. 표본은 시드 고정이라 같은 옵션이면
같은 URL이 뽑힌다 — 엔진을 고친 전후를 비교할 수 있다.

## 읽는 법: "피드 제외" 칸이 진짜 점수다

URLhaus와 OpenPhish는 **우리 엔진의 입력이기도 하다** (S3·S2). 그 목록으로
점수를 내면 정답지를 보고 푼 시험이 된다. 그래서 판정을 두 번 계산한다.

| 칸 | 뜻 |
| --- | --- |
| 엔진 그대로 | 사용자가 실제로 받는 판정 |
| 피드 제외 | S2·S3를 빼고 나머지 시그널만으로 재판정 |

정상 코퍼스(Tranco)는 우리 입력이 아니므로 두 칸이 거의 같다. 여기서는
**`danger` 칸이 0에 가까운지**만 보면 된다 — 오탐이 미탐보다 비싸다.

## 안전과 비용

- **대상 사이트에 실제로 접속한다.** `scan()`을 직접 부르므로 SSRF 가드
  (`lib/scanner/guard.ts`)를 그대로 통과하지만, 살아 있는 멀웨어 호스트 수십 곳에
  집에서 접속하게 된다는 사실은 알고 돌릴 것.
- **캐시·DB를 건드리지 않는다.** `/api/scan` 라우트가 아니라 `scan()`을 부르기
  때문에 Redis 캐시와 Supabase에 벤치 결과가 섞이지 않는다.
- **Claude를 호출하지 않는다.** 설명 레이어는 판정에 관여하지 않아 비용만 든다.
- `bench/data/`와 `bench/out/`은 악성 URL 원문이 들어 있어 `.gitignore`에 있다.
- `--vt`를 켜면 **검사 URL이 VirusTotal로 전송된다.** 공개된 코퍼스에만 쓸 것.
  무료 키는 분당 4회라 100건에 27분쯤 걸린다.

## 2026-08-15 결과

| 코퍼스 | 표본 | 엔진 그대로 | 피드 제외 |
| --- | --- | --- | --- |
| OpenPhish (피싱) | 100 | danger 100% | danger 20% · 미탐 71% |
| URLhaus (멀웨어) | 100 | danger 16% · caution 49% | 미탐 88% |
| Tranco 1만~50만위 (정상) | 200 | **danger 0%** · caution 1.5% | danger 0% |

### S11(본문 검사)을 붙인 뒤 — 같은 표본 재측정

| 코퍼스 | 피드 제외 danger | 미탐 | S11 적중 |
| --- | --- | --- | --- |
| OpenPhish 100 | 20% → **29%** | 71% → 60% | 11% |
| Tranco 200 (정상) | 0% → **0%** | — | **0%** |

정상 코퍼스에서 S11이 한 건도 걸리지 않은 채로 탐지만 올랐다. 남은 미탐의
성격은 아래 "읽어낸 것" 2번에 적은 것과 다르다 — 이제는 로그인 폼이 없는
경품·크립토 사기 페이지가 대부분이라, 자격증명 시그널로는 원리상 못 잡는다.

읽어낸 것:

1. **오탐은 아직 없다.** 정상 도메인 200개에서 `danger` 0건. 상위권만 뽑지 않고
   1만~50만위 구간에서 뽑았는데도 그렇다.
2. **피드를 빼면 피싱 탐지가 20%로 떨어진다.** 그 20%도 전부 S1(구글)이 잡은
   것이고, 우리가 직접 만든 S7(브랜드 사칭)은 **100건 중 0건**을 잡았다.
   요즘 피싱은 도메인에 브랜드명을 넣지 않는다 — 표본의 69%가
   `vercel.app`·`github.io`·`workers.dev` 같은 무료 호스팅의 랜덤 서브도메인이었다.
   S7은 `kbst4r.com` 시대의 공격을 겨냥한 시그널이다.
3. **URLhaus는 우리 잣대가 아니다.** 표본의 47%가 도메인 없는 생 IP 주소였다.
   봇넷 페이로드 배포 인프라이지 사람이 문자로 받는 링크가 아니다.
4. **구글과 URLhaus는 거의 겹치지 않는다.** URLhaus 100건 중 구글이 아는 것은
   0건이었다. (구글 공개 테스트 URL로 S1 연동은 정상 동작을 확인했다.)
5. **S3의 호스트 단위 매칭이 정상 사이트를 건드린다.** Tranco 200건 중 3건이
   `caution`이 됐는데 전부 S3 호스트 일치였다. 한때 뚫렸다가 복구된 사이트로
   보인다. 지금은 `caution`까지만 올라가서 큰 피해는 없지만, 피드가 커지면
   이 비율도 같이 커진다.

### 한국어 코퍼스 — KISA 피싱 URL (2026-08-16 추가)

공공데이터포털의 한국인터넷진흥원 피싱사이트 데이터. **연 1회 스냅샷**이라
실시간 피드로는 못 쓰지만, 한국 브랜드를 사칭한 실제 주소 13만 건이라
교차검증 코퍼스로는 정확히 필요한 물건이다.

```bash
# 매년 파일 ID가 바뀐다. 상세 페이지에서 atchFileId 를 먼저 찾을 것
curl -s 'https://www.data.go.kr/data/15143094/fileData.do' -H 'user-agent: Mozilla/5.0' \
  | grep -oE 'atchFileId=[A-Za-z0-9_]+' | head -1
curl -sL "https://www.data.go.kr/cmm/cmm/fileDownload.do?atchFileId=<위 ID>&fileDetailSn=1" \
  -H 'user-agent: Mozilla/5.0' -o /tmp/kisa.raw
# UTF-8 with BOM. EUC-KR로 읽으면 통째로 깨진다
tail -n +2 /tmp/kisa.raw | sed $'s/\r//; s/^\xef\xbb\xbf//' | cut -d, -f2 \
  | grep -v '^$' > bench/data/kisa-2024.txt
```

1~2년 전 주소라 대부분 죽어 있어 **본문 검사(S11)는 잴 수 없다.**
주소만 보는 S7과 브랜드 목록은 접속 없이 전량 검증할 수 있다.

🚨 원본 131,752행에는 같은 주소가 여러 날짜로 반복된다. **중복을 제거하고**
세야 한다 — 기록 수를 분모로 쓰면 오래 살아남은 주소가 여러 번 세어져
적중률이 부풀려진다 (그렇게 재면 9.07%가 나온다).

| | 값 |
| --- | --- |
| 고유 URL | 37,478건 (기록 131,752행) |
| 고유 등록도메인 | 6,106개 |
| S7 적중 | **3.40%** (1,274건) |
| 무료 호스팅 위 | **0.00%** |
| 사칭 1위 | 정부24 (1,129건 = 적중의 89%) |
| TLD | `.kr` 18.9% · `.co` 7.0% · `.gl` 5.7% · `.ly` 5.1% |

### 수명 — 무엇이 오래 남는가

| 목록에 등장한 기간 | URL | 등록도메인 |
| --- | --- | --- |
| 하루 | 42.1% | 23.1% |
| 2~7일 | 24.8% | 10.9% |
| 8~30일 | 15.8% | 23.5% |
| 31일 이상 | 17.4% | **42.5%** |

**도메인이 URL보다 훨씬 오래 산다.** 신고를 URL 단위로 쌓으면 42%가 하루 만에
쓸모없어지지만, 도메인 단위로 쌓으면 42.5%가 한 달 넘게 유효하다.
`domains.report_count` 가 도메인 단위인 것은 이 점에서 맞는 설계다.

정부24 캠페인은 그 반대 극단이다 — URL 1,129개가 등록도메인 1,099개를 쓴다.
거의 한 번 쓰고 버린다. 그런데 **1,099개 전부가 같은 모양이다**: `gov.` +
4글자 무작위 라벨 + 싸구려 TLD(`.work` 242, `.icu` 168, `.lat` 104…).
목록으로는 못 따라가고, 규칙 하나로는 전부 덮인다.

**해외 코퍼스와 정반대다.** 해외 피싱은 70%가 무료 호스팅인데 한국은 0이다.
싸구려 도메인을 직접 산다. 해외에서 **0%**였던 S7이 여기서는 **3.4%**를 잡는다 —
한국 스미싱용으로 만든 시그널이 실제로 한국에서만 작동한다는 뜻이다.

### 놓친 96.6%를 뜯어보고 만든 것 — S12

S7이 KISA 표본의 3.4%만 잡았으므로, **나머지가 어떻게 생겼는지**를 봤다.
놓친 것의 84%가 등록 이름 4글자 이하였고, 숫자가 글자 사이에 낀 형태였다.

| 조건 | KISA(악성) | Tranco 1~1만 | 1만~10만 | 10만~100만 |
| --- | --- | --- | --- | --- |
| ≤4글자 | 68.5% | 17.24% | 12.12% | 7.05% |
| ≤4글자 + 흔치 않은 TLD | 65.0% | 6.57% | 5.12% | 3.43% |
| ≤4글자 + 숫자 혼합 | 56.7% | 1.08% | 1.07% | 1.16% |
| **≤4글자 + 숫자가 가운데** | **55.6%** | **0.18%** | **0.20%** | **0.15%** |

마지막 줄만 쓸 수 있다. TLD 목록에 의존하지 않고(유지할 목록이 하나 줄고),
순위 구간과 무관하게 오탐률이 평평하다. `1drv.ms`·`ic3.gov`·`tv2.no`는
숫자가 가장자리에 있어 자동으로 빠진다.

0.15%도 0은 아니다 — `g2a.com`, `n8n.io`가 걸린다. 그래서 `medium` 으로 두고
단독 판정을 막았다.

### 검사 시간 — 죽은 주소가 가장 느렸다

이미 내려간 스미싱 URL 80건을 실제로 검사한 결과다. 살아 있는 사이트(Tranco)는
중앙값 2.5초인데 여기서는 30.6초가 나왔다. 스미싱 링크는 대개 이미 죽어 있으므로
**실사용에서 가장 흔한 경로가 가장 느렸다.**

| | 중앙값 | p95 | 오류 |
| --- | --- | --- | --- |
| 처음 | 30.6초 | 45초 | 17건 |
| DNS 3초 상한 후 | 7.0초 | 45초 | 5건 |
| 전체 예산 20초 후 | **7.0초** | **20초** | **0건** |

```bash
npm run bench -- --urls bench/data/kisa-sample.txt --limit 80
```

### 기각된 시그널

**남의 사이트 리소스 빌려 쓰기** — 피싱 46% vs 정상 84%로 **반대 방향**이었다.
정상 사이트가 광고·트래커·위젯을 수십 곳에서 불러오기 때문이다. 브랜드 공식
도메인으로 좁혀도 재현율 4%. 코드와 근거는 `bench/assets.ts`.

남은 한계는 **살아 있는** 한국 표본이 없다는 것이다. KISA 데이터는 작년치라
대부분 이미 내려갔고, 그래서 주소를 보는 S7은 검증했지만 페이지 내용을 읽는
S11은 한국어로 아직 검증하지 못했다.

### VirusTotal 대조

우리가 놓친 피싱 40건을 VT에 물어봤더니 **40건 전부 악성**이었다. 건당 3~19개
엔진이 탐지했고 중앙값은 10개다. 코퍼스 라벨이 낡은 게 아니라 우리가 실제로
놓친 것이 맞다는 뜻이다.

```bash
npm run bench -- --urls bench/data/openphish-misses.txt --limit 40 --vt
```

## 본문 프로브 (`bench:probe`)

주소만 봐서는 못 잡는다는 게 확인됐으므로, 페이지 본문을 보는 시그널 후보를
붙이기 전에 재보는 도구다.

```bash
npm run bench:probe -- --urls bench/data/openphish-misses.txt
npm run bench:probe -- --set tranco --limit 200 --band 10000-500000
npm run bench:probe -- --urls ... --browser-ua   # 클로킹 영향 측정
```

이미 내려간 페이지(404·호스팅 업체 차단·1KB 미만)는 분모에서 뺀다. 놓친 71건
중 25건이 이미 죽어 있었다 — 그걸 분모에 넣으면 "잡을 게 없던 건"까지 미탐으로
세게 된다.

### 2026-08-15 측정

| 후보 | 피싱 46건(살아있음) | 정상 126건(살아있음) |
| --- | --- | --- |
| 무료 호스팅 서브도메인 | 70% | 0% |
| 비밀번호 입력란 | 22% | 10% |
| 제목에 남의 브랜드 | 37% | 0% |
| 폼이 남의 도메인으로 전송 | 11% | 5% |
| **브랜드 + 자격증명칸** | **17%** | **0%** |
| **무료호스팅 + 비밀번호** | **22%** | **0%** |

단독으로 쓸 수 있는 후보는 없다. 비밀번호 입력란은 정상 사이트의 10%에도
있다 — 로그인 페이지는 원래 다 그렇다. **조합일 때만 의미가 있다.**

곁가지로 확인된 것 두 가지:

- **클로킹은 원인이 아니었다.** 브라우저 User-Agent로 바꿔 다시 재도 숫자가
  한 자리도 안 바뀌었다. 봇이라고 정직하게 밝히는 기본값을 유지해도 손해가 없다.
- **헤드리스 브라우저가 급하지 않다.** JS로 폼을 그리는 SPA 껍데기는 46건 중
  1건뿐이었다. 정적 HTML 파싱으로 대부분 덮인다 — 스크린샷 워커(Sprint 4)를
  앞당길 이유가 없다.

### 무료 호스팅 위의 정상 사이트 (`--set freehost`)

Tranco 상위 50만 위 안에는 `vercel.app`에 올린 개인 프로젝트가 아예 없다 —
순위 목록은 등록가능 도메인 단위라 무료 호스팅 서브도메인이 한 건도 없다.
그래서 `무료호스팅 + 비밀번호` 조합의 오탐이 날 자리 자체가 코퍼스에 없었다.

GitHub에서 따로 모았다. 자기 프로젝트를 무료 호스팅에 올리고 그 주소를 저장소
설명에 적어둔 사람들이다.

| | 살아 있는 112건 |
| --- | --- |
| 무료 호스팅 서브도메인 | 77% |
| 비밀번호 입력란 | **0%** |
| 아이디/이메일 입력란 | 4% |
| **무료호스팅 + 비밀번호** | **0%** |

개인 프로젝트는 블로그·포트폴리오·문서라서 남의 비밀번호를 받지 않는다.
이 결과를 근거로 그 조합을 `medium` → `high`(caution)로 올렸다.
danger 로 올리지 않는 이유는 표본이 GitHub에서 찾을 수 있는 프로젝트에
치우쳐 있어서다 — 로그인이 있는 습작 SaaS가 덜 잡혔을 수 있다.
